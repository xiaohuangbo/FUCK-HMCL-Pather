### `LocaleUtils.IS_CHINA_MAINLAND` 是如何判定的？

**这个常量在本 PR 中已经被移除/替换了**，原来的判断逻辑比较简单，现在被更复杂的 `RegionUtils` 取代。

#### 旧的 `LocaleUtils.IS_CHINA_MAINLAND`（已被替换）
从 PR 的 diff 可以看出，它之前被直接用于各种地方，但具体实现比较粗糙（主要依赖系统 Locale / 时区等信息）。本 PR 把它彻底换成了 `RegionUtils`。

#### 现在的判定逻辑（`RegionUtils`）

分两层：

**1. 机器是否在中国大陆（`IS_CHINA_MAINLAND_MACHINE` / `isIsChinaMainlandMachine()`）**

静态初始化时执行 `checkMachineIsChinaMainland()`：

```java
if ("Asia/Shanghai".equals(ZoneId.systemDefault().getId()))
    return true;

// 时区是 UTC+8
if (ZonedDateTime.now().getOffset().getTotalSeconds() == Duration.ofHours(8).toSeconds()) {
    if ("CN".equals(LocaleUtils.SYSTEM_DEFAULT.getCountry()))
        return true;

    // Windows + 使用 JNA 时
    if (Windows && GetUserGeoID(GEOCLASS_NATION) == 45)  // 45 = China
        return true;
}

return false;
```

也就是说，满足以下任一条件就认为是“大陆机器”：
- 系统时区是 `Asia/Shanghai`
- 时区偏移是 UTC+8 **并且** 系统国家是 `CN`
- Windows 下通过 `GetUserGeoID` 拿到地理区域 ID 为 45（中国）

**2. 网络是否在中国大陆（`isIsChinaMainlandNetwork()`）**

只有机器先被判定为大陆时，才会进一步检查网络：

- 请求 `https://ipwho.is`
- 解析返回的 `country_code`
- 如果请求失败 **或** `country_code` 是 `CN`，则返回 `true`（视为大陆网络）
- 结果会缓存（`volatile Boolean`）

下载页面真正禁用功能时，用的是 `isIsChinaMainlandNetwork()`（机器 + 网络双重判断）。

### 补充说明

- 机器判断比较宽松（时区 + 国家/地理 ID），网络判断会真正去查 IP 归属。
- 有用户在讨论中提到可以通过改时区/系统区域（比如设成新加坡）绕过机器判断。
- 下载禁用只影响启动器内的游戏版本下载界面，其他功能（正版登录、启动已有版本等）不受影响。
